# Internal correction-memory development evaluation

Evidence: [internal-results.json](internal-results.json), generated by
[runner.py](runner.py). This is an exploratory development set, not a held-out
benchmark. Source logs, corpus and query cases remain private. Public reproduction
uses the packaged synthetic demo; exact private reproduction requires the matching
corpus and cases hashes in the receipt.

On 2026-10-20, the owner authorized the local Codex logs for internal use. The
existing miner scanned 5,938 JSONL files and extracted 16 correction episodes;
15 have an original prompt eligible for the existing embedding index. Only six
match the compiler's fixed advice buckets. These are miner outputs, not an
estimate of how many corrections actually occurred or evidence of mining recall.

Five subsequent-task queries were written after inspecting the corpus, each with
an annotated target episode (one accepts either of two duplicates). Two unrelated
queries test abstention. Top three results are allowed. Local embeddings use
Ollama `nomic-embed-text`, dimension 768, and the existing 0.4 cosine floor.
Hybrid uses reciprocal rank fusion with constant 60 over dense and keyword ranks.
The keyword baseline is transparent token overlap weighted by document frequency;
it searches original prompts plus corrections. Dense search uses original-prompt
embeddings from the existing compiler index.

| Method | Target found | Unrelated query returned no evidence |
|---|---:|---:|
| Keyword (offline default) | 5/5 | 1/2 |
| Semantic (local Ollama) | 1/5 | 1/2 |
| Hybrid (local Ollama) | 4/5 | 1/2 |

The default remains keyword retrieval because embeddings add local runtime
requirements without improving this measured set. Initially, common function
words caused both negative queries to retrieve evidence; a conventional stopword
filter was added before the reported run. These negatives are therefore also
development cases. Do not present them as independent generalization evidence.
The positive triage query also informed the hybrid implementation. No threshold
sweep, statistical significance claim or behavioral win rate is reported.

A native keyword search can recover the same evidence from this small corpus.
A standing instruction can encode a known correction with less machinery; it
requires someone to select and maintain that instruction, and loses episode
provenance unless manually retained. Always including every correction trivially
covers the targets but adds the full corpus to each task; the receipt records
that character count. Character counts are not model token counts.

Remaining limitations: false positives on unrelated prompts, sparse and biased
owner-only data, duplicate episodes, category coverage gaps, no exhaustive relevance
labels, no agent-behavior comparison, and no measured productivity improvement.
A [fresh Codex session](fresh-session-results.json), with no inherited conversation,
followed an isolated project's AGENTS.md instruction, invoked the installed tool,
and cited the real triage episode in a proposed internal next action. This is one
read-only tool-use check, not a behavior-improvement experiment or proof of global
hook delivery. The [installed demo receipt](installed-demo-results.json) separately
records the synthetic fixture and live local embedding continuation.


## Public reproducible check

The [public corpus and query cases](public/README.md) contain no private logs.
Labels were frozen before execution after the 0.1.14 algorithm was written; this
is a public regression set, not an independently sampled or held-out benchmark.
No retrieval algorithm or threshold was changed after observing these results.
The [receipt](public/results.json) records source and corpus identities and the
per-case misses, with three candidates permitted per task.

| Method | Target found | Unrelated query returned no evidence |
|---|---:|---:|
| Keyword (offline default) | 15/18 | 4/8 |
| Semantic (local Ollama) | 18/18 | 2/8 |
| Hybrid (local Ollama) | 18/18 | 2/8 |

On this public set, embeddings recover the paraphrases missed by keyword search
and return more evidence on unrelated tasks. This differs from the private
development set; neither establishes a general winner. Questions that share a
domain word with a correction account for the offline false positives. The
interface returns historical search candidates, not a relevance verdict or
instructions to apply automatically.

The offline suite runs in pytest with the observed target and abstention counts
as regression floors; improvements can exceed those floors. The evaluator
rejects nonexistent target rows, duplicate case IDs and empty queries, so a
misconfigured case file cannot silently count them as a quality measurement.

The 0.1.15 maintenance candidate was also checked in a
[fresh Codex session](fresh-session-0.1.15.json) using its installed wheel against
the real private corpus. The session ran recall successfully and cited the triage
episode in its next-action proposal. The runtime retrieval source is byte-identical
to the internally verified 0.1.14 source; onboarding, public evaluation data and
evaluator input validation are the changes. See the
[release check receipt](release-0.1.15.json).
